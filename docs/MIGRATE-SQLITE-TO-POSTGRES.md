# Migration plan: better-sqlite3 -> Postgres

Status: **implemented.** The arena-hardened plan below was executed on branch
`migrate-to-postgres`. One deviation: `@>`/`unnest` facet queries are not
unit-tested under pg-mem (it cannot run them); they are covered by the
real-Postgres verification probe instead. The one-time `pnpm load-from-sqlite`
script reads `worlds.db` via Node's built-in `node:sqlite`; `better-sqlite3`
has been removed from the dependency list.

## Goals & scope

- Move the API's persistence from embedded better-sqlite3 to a client-server Postgres,
  using the raw `pg` driver with async repositories.
- **API-only.** The VRChat bot already forwards data to the API over HTTP
  (`POST /api/worlds`, `/api/worlds/pairs` is its crawl-cache helper); it does not touch
  the database file. No bot changes.
- One-time data-load from the existing `worlds.db` so no history is lost.
- Postgres runs on the same droplet as the API (cost), bound to `127.0.0.1`. Because
  Postgres is client-server, moving to another droplet later is `pg_dump` + restore +
  a `DATABASE_URL` change.

## Non-negotiable findings (from the arena review)

These are correctness blockers that must be in any implementation, regardless of style:

1. **The hotspot: `src/apiServer/middleware/auth.ts`.** `findByHash` (`:37`) and
   `touchLastUsed` (`:56`) run a DB read + write on every authenticated request. Both
   must become async (Express 5 auto-forwards rejected promises to the sanitizing
   `errorHandler`). `routes/health.ts:7` (`count()`) too. `me.ts` touches **no** DB —
   do not churn it.
2. **`package_sizes` is `double precision[]`, never `int[]`.** Values are MB floats
   (`packageSizes.ts:42` `bytes/1048576`; tests assert `[104.5, 78.2]`).
3. **pg decode-drift.** `COUNT(*)`/`bigint`/`numeric[]` come back as JS **strings**, so
   `rowToRecord` epoch fields, `count()`/`total`, and `packageSizes` would become strings
   and break strict comparisons. Fix once in `src/db/mappers.ts`: `COUNT(*)::int`,
   `Number()` in `rowToRecord`, `double precision[]`. (Note: the `apiServer.*` suites mock
   the repos and return plain numbers, so they do **not** expose the drift — assert it in
   the real-DB repo tests `worldRepository.test.ts` / `tokenRepository.test.ts` instead.)
4. **`EXTRACT(EPOCH FROM NOW())::bigint`** — the cast is mandatory; without it the first
   migration errors on integer columns.
5. **Filter semantics.** Tag/platform filters are AND today (one `EXISTS(json_each…)`
   per tag, `worldRepository.ts:385-401`). Replace with `@> ARRAY[…]` (contains-all), NOT
   `&&` (which silently flips to OR). `getUniqueTags`/`getMetadataCounts` need `unnest`,
   not `@>`/`&&`.
6. **Mechanical rewrites:** `result.changes`→`rowCount` (7 sites), 
   `lastInsertRowid`→`INSERT … RETURNING id` (2 sites), `db.transaction`→async
   `withTransaction`.

## Phase 0 — deps, config, client seam

- Add `pg` + `@types/pg`; add `pg-mem` (dev, needed by Phase 5). **Keep
  `better-sqlite3` as a devDependency** (one-time load reader only); remove it after
  Phase 7.
- `src/config.ts`: add `DATABASE_URL`. Keep `DATABASE_PATH` only for the load script until
  Phase 8. Add `TEST_DATABASE_URL` for the integration suite.
- New `src/db/client.ts`:
  ```
  interface Queryable {
    query(text: string, values?: unknown[]): Promise<QueryResultLike>;
    withTransaction<T>(fn: (q: Queryable) => Promise<T>): Promise<T>;
  }
  ```
  Every repo + `runMigrations` + every test injects `Queryable` — never `pg.Pool`
  directly. This is the seam that lets pg-mem's pool stand in.
- Centralized mapper module (`src/db/mappers.ts`): `Number()`, `COUNT(*)::int`,
  float-array decode — one place for the pg string-typing problem.

## Phase 1 — connection layer (`src/db/index.ts`)

- Singleton → lazily-created `pg.Pool` from `DATABASE_URL` (lazy, not at import, so
  jest-mocked config never builds a live pool).
- `query()` helper; async `withTransaction()` = `pool.connect()` +
  `BEGIN/COMMIT/ROLLBACK`.
- `closeDatabase(): Promise<void>` (`await pool.end()`, null the instance).
- Drop the WAL / `foreign_keys` pragmas (`index.ts:22-23`) — PG has no per-connection
  pragmas; FK enforcement is always-on in PG (opposite of SQLite's default OFF).

## Phase 2 — schema port (`src/db/schema.ts`)

- `AUTOINCREMENT` → `GENERATED BY DEFAULT AS IDENTITY` (or bigserial). Epoch columns
  `BIGINT NOT NULL DEFAULT (EXTRACT(EPOCH FROM NOW()))::bigint`.
- `?` → `$n`. Conditional `ADD COLUMN` via `information_schema.columns` filtered on
  `table_schema = 'public'` (003/005/007) — or `ADD COLUMN IF NOT EXISTS`.
- `INSERT OR IGNORE` → `ON CONFLICT DO NOTHING`; `excluded.` → `EXCLUDED.`.
- **Native array columns** (the PG schema is built fresh from scratch in this migration, so
  these are created natively — no live-PG data to normalize; the existing SQLite JSON
  strings are converted during the one-time load in Phase 7):
  - `tags text[] NOT NULL DEFAULT '{}'`
  - `platforms text[] NOT NULL DEFAULT '{}'`
  - `package_sizes double precision[] NOT NULL DEFAULT '{}'`
  - `roles.permissions text[] NOT NULL DEFAULT '{}'`
- Migration 006 seed roles as array literals; migration 009 reads/mutates `permissions`
  as a native array (drop `JSON.parse`/`JSON.stringify` — PG already returns a JS array).
- **GIN indexes:** `CREATE INDEX … USING GIN ((tags))`, `USING GIN ((platforms))`.
- Runner: becomes async; per-migration `withTransaction` (PG DDL is transactional, so
  `migration.run` + `_migrations` insert stay atomic). `_migrations`:
  `(name text PRIMARY KEY, applied_at bigint DEFAULT (EXTRACT(EPOCH FROM NOW()))::bigint)`.

## Phase 3 — repos async + exact query rewrites

All 4 repos (`world`/`token`/`role`/`highPriority`) become async over `Queryable`:
`stmt.run`→`await query`; `changes`→`rowCount`; `lastInsertRowid`→`RETURNING id`.

- **`WorldRepository`**
  - `upsert`: `ON CONFLICT(world_id,guild_id) DO UPDATE … EXCLUDED.x`; arrays as params.
  - `deleteByWorldAndGuild`: `db.transaction`→`withTransaction`.
  - `getAllWorldGuildPairs` (`:342`): return structured `{worldId,guildId}` rows instead
    of `world_id||'-'||guild_id` keys + `lastIndexOf('-')` split (`worlds.ts:151`). Not
    broken for current ids (no dashes), but the key round-trip is fragile — fix it here.
  - `buildWhereClause` (`:353-447`):
    - tags: `wr.tags @> $n::text[]` (AND preserved)
    - platforms: `wr.platforms @> $n::text[]`
    - search: `name ILIKE $n OR author_name ILIKE $n OR source_content ILIKE $n OR
      world_id ILIKE $n OR EXISTS(SELECT 1 FROM unnest(wr.tags) t WHERE t ILIKE $n)`
    - dayRange (`:431-435`): compute `cutoff = Math.floor(Date.now()/1000) - dayRange*86400`
      in JS and bind `$n` (don't `strftime` / interpolate).
    - counts: `SELECT COUNT(*)::int as total …`.
  - `getMetadataCounts` (`:526-536`) & `getUniqueTags` (`:566-573`): `json_each` → `unnest`.
  - `rowToRecord` (`:26-52`): drop `safeJsonParse` for arrays; `Number()` epoch/bigint
    fields; map PG `NULL`/`{}`→`[]`.
- **`HighPriorityRepository`**: `ON CONFLICT(world_id,guild_id) DO NOTHING`; `rowCount`
  `0` on conflict ⇒ `added:false` (preserved).
- **`TokenRepository`/`RoleRepository`**: `RETURNING id`; array permission params.
- Keep `hashToken`/`generateRawToken` pure/sync (they don't touch the DB).

## Phase 4 — async the remaining callers (traced, not checklist)

- **`middleware/auth.ts`**: `await findByHash`; make `touchLastUsed` fire-and-forget
  (`void …`) so the hot path doesn't slow.
- **`routes/health.ts`**: `await count()`.
- Routes: `worlds.ts` (all GET handlers incl. `/pairs`), `worldsMutations.ts` (DELETE,
  quality, tags, tags/edit, high-priority add/remove), `tags.ts`, `meta.ts`.
- `worlds/service.ts`: `await` repo calls (`:77,80,116`).
- `tokens/cli.ts`: conversion is broader than help text. `requireRole` (`:92`), every
  `cmd*` handler (`cmdTokenCreate/List/Revoke`, `cmdRoleList/Create/Update`) and the
  top-level `switch` (`:172`) all call async repos. Make them `async`/`await` through an
  async `main()`. `printUsage` (`:57`) also calls `list()`.
- `scripts/backfill-package-sizes.ts`: **full async rewrite** — it uses sync
  `db.prepare().get()/.all()/.run()` and `JSON.stringify(sizes)` throughout (`:28-64`).
  Convert to `await query(...)` with `COUNT(*)::int`, native array binding (no
  `JSON.stringify`), and `cardinality(package_sizes) = 0` for the empty predicate.
- `me.ts`: **no change** (no DB call).

## Phase 5 — tests (precisely scoped)

- **pg-mem only for the 3 real-DB suites**: `worldRepository.test.ts`,
  `tokenRepository.test.ts`, `highPriorityRepository.test.ts`. `newDb().adapters.createPg()`
  drop-in pool; drop `pragma('foreign_keys = ON')`; `await runMigrations(pool)`; async
  asserts; array equality (not JSON strings). Assert `rowToRecord` returns **numbers** (not
  strings) for `created_at`/`total`/`packageSizes` — this is where pg decode-drift surfaces.
- **Rewrite the migration-009 test** (`worldRepository.test.ts:105-164`) for
  `permissions text[]` (array equality).
- **5 mock-based suites** (`apiServer.test.ts`, `.mutations`, `.highPriority`, `.me`,
  `worlds/service.test.ts`) mock the repos: `jest.fn()`→`mockResolvedValue`. No pg-mem.
- **`backup-db.test.ts`**: mock `pg_dump` via `child_process`; drop the `'SQLite format 3'`
  magic (`:65`) and `journal_mode` (`:100`) asserts; keep retention/prune coverage.
- **Fallback**: compute epoch/interval values in JS and parameterize (avoids pg-mem fragile
  spots like `INTERVAL … * $n`); last resort a real ephemeral Postgres for that one suite.
- **Add env-gated real-Postgres integration suite** (`TEST_DATABASE_URL`) covering `@>`,
  `&&`, `ILIKE`, `unnest`, `ON CONFLICT`, and `runMigrations` where pg-mem can't.

## Phase 6 — backup (`src/scripts/backup-db.ts`)

- Replace `source.backup()` + WAL→DELETE normalization + `integrity_check`
  (`:38-57`) with **`pg_dump -Fc`** shell-out using `DATABASE_URL`. Custom format already
  compresses — drop the extra gzip. Verify with `pg_restore -l` (list), not `integrity_check`.
- Update `BACKUP_FILE` regex (`:16`) and naming to `.dump`.
- `createBackup` signature: `dbPath` → `DATABASE_URL`.
- Update restore flow in `docs/BACKUP.md` (`pg_restore`, drop the `worlds.db-wal` /
  `worlds.db-shm` removal).
- Ensure `pg_dump` is installed on the production droplet.

## Phase 7 — one-time data-load (`src/scripts/load-from-sqlite.ts`)

- Read `worlds.db` with Node's built-in `node:sqlite` (`DatabaseSync`, read-only),
  **API stopped**.
- **Load in FK order**: `roles` → `api_tokens` → `world_records` →
  `deleted_world_records` → `high_priority_worlds` (composite FK to
  `world_records(world_id,guild_id)` and `added_by_token_id`→`api_tokens`). Each
  `ON CONFLICT DO NOTHING`.
- **Roles collision**: migration 006 seeds `viewer`/`curator`/`admin` on the fresh PG, so
  their `id`s (1,2,3) differ from the source DB's. Do **not** insert roles by explicit id
  blindly — resolve `api_tokens.role_id` by **role name** (look up the target PG role id),
  and skip re-inserting seeded roles that already exist.
- Convert JSON-string columns to JS arrays (pg serializes to array literals).
- **Reseed sequences**: `SELECT setval(pg_get_serial_sequence('<table>','id'),
  COALESCE(MAX(id),1))` for every id-bearing table, or the next insert collides.
- **Seed `_migrations`** with all migration names, or fresh PG re-runs migrations on the
  loaded data and re-seeds roles.
- Verify: row-count parity per table + spot-check one `high_priority_worlds` FK.

## Phase 8 — config, docs, deploy

- `DATABASE_PATH` → `DATABASE_URL` across `config.ts`, `.env.sample`, `README.md`,
  `docs/API.md`, `docs/BACKUP.md`, `backup-db.ts`. Confirm consumers: `index.ts` + load
  script. (Note: `ecosystem.config.js` does **not** reference the DB — no change.)
- `better-sqlite3` + `@types/better-sqlite3` removed; the load script reads
  `worlds.db` through Node's built-in `node:sqlite` instead.
- Postgres on droplet: bind `listen_addresses` / `pg_hba.conf` to `127.0.0.1`, strong
  password, not exposed publicly.
